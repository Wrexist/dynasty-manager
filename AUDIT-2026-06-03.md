# Fixes applied in this branch

The following Critical/High findings were fixed and verified (typecheck + lint + full test
suite + build green; new regression tests added for the cup `winnerId` and season-award fixes):

1. **PL 38-week season-end** — ends the season on `state.totalWeeks` (`weekAdvance.ts`).
2. **Subbed-off match credit** — appearances/morale/fitness credited to the starting XI + anyone
   subbed off, reconstructed from substitution events (`matchProcessing.ts`).
3. **Cup / League-Cup `winnerId`** — set on every resolved tie; penalties no longer inflate the
   score; `advanceCupRound`/`advanceLeagueCupRound` reuse the stored winner (`cup.ts`, `weekAdvance.ts`).
4. **Continental finals** — final excluded from the generic leg-1 branch so the winner resolves (`continental.ts`).
5. **AI finance** — `estimateWeeklyIncome` no longer returns max prize on an empty table (`aiSimulation.ts`).
6. **Sponsor promotion** — `promoted` derived from `promotionSpots`; season-end applies only the
   sponsor budget *delta* (`sponsorSlice.ts`, `seasonEnd.ts`).
7. **Career promotion/relegation reputation** — keyed on promotion/relegation spots (`seasonEnd.ts`).
8. **Youth** — OVR via `calculateOverall`; un-promoted youth records pruned each season (`weekAdvance.ts`, `seasonEnd.ts`).
9. Also: `usePlayerClub` type, advance-week double-fire, scout fog + scout-growth week,
   ObjectiveContext stale cup ties, `internationalCaps` spread, unemployed-week AI tick,
   save-stringify try/catch, season-award division scoping + young-player appearances,
   history top-scorer scoping, `loanOut` squad floor, `renewContract` wage-bill floor,
   Hall-of-Managers key constant, free-trial re-extension, LoanNegotiation false success.

**Investigated, intentionally NOT changed:** the AI sell-candidate `break` — verified `break`/`continue`
are equivalent here (candidates ≠ sales; no-sell at min squad is intended). The flag was a false positive.

**Deferred (larger/riskier rework, tracked):** transfer approach for *unlisted* players;
SubstitutionSheet double-optimizer; international group double-booking; Finance headline-vs-breakdown
unification; ad-reward atomicity / PacksPage sell-all race (store likely already guards double-claim);
buyLoanedPlayer stale listing; continental R16 same-group fallback; assorted save-migration polish.

# CRITICAL & HIGH-PRIORITY BUGS

### 1. ✅ Premier League season has 8 dead weeks (season never ends on time)
`src/store/slices/orchestration/weekAdvance.ts:665`
The season-end trigger is `if (newWeek > TOTAL_WEEKS)` where `TOTAL_WEEKS = 46` is a hardcoded
constant (`gameBalance.ts:9`). But the PL is a 38-week league (`england.ts:10 totalWeeks: 38`),
and `state.totalWeeks` is correctly set to 38 at init (`initGame.ts:467`) with fixtures generated
for 38 weeks. Result: a PL save plays its last fixture in week 38, then the player must click
through **8 empty weeks (39–46)** before `endSeason()` fires at week 47 — while training, contract
warnings, and board-confidence decay keep ticking on a finished season. **Fix:** compare against
`state.totalWeeks`, not the global constant. (Severity: High→Critical for top-flight UX.)

### 2. ✅ Subbed-off players lose all match credit (appearances / morale / fitness)
`src/store/helpers/matchProcessing.ts:86,112` + `src/store/slices/matchSlice.ts:199-200,220`
`makeMatchSub` rewrites `club.lineup` in the store (replaces the out-player with the sub and pushes
the out-player to `subs`). `processMatchResult` then awards appearances and the "played" morale boost
by iterating the **post-sub** `lineup` (line 86), and builds `matchParticipants` from it (line 112).
So a starter subbed off at 89' gets **no appearance, no morale boost, and no fitness drain**, while
the sub who played 5 minutes drains a full match. Happens on every interactive match where the human
makes a substitution; corrupts appearance totals (which feed milestones, records, contracts).

### 3. ◐✅ Penalty-decided cup/league-cup ties never store `winnerId` → wrong winner shown
`src/data/cup.ts:108-130` (AI rounds) · `weekAdvance.ts:1109,1201` (player-week sims) ·
`CupPage.tsx:18` / `LeagueCupPage.tsx:19` / `KnockoutBracket.tsx:42,146`
Drawn ties compute the real shootout winner (used correctly for bracket advancement) and store the
`penaltyShootout` score, but **never set `tie.winnerId`**. `CupPage`/`LeagueCupPage` fall back to
`homeGoals > awayGoals ? home : away`, which for any 0-0/1-1 penalty tie resolves to the **away team**
regardless of who actually won. `KnockoutBracket.tsx` has *no* fallback — it treats `winnerId`
(`undefined`) as "decided" but highlights neither team, and `roundTies.every(t => t.winnerId !== null)`
is `true` for unplayed-looking ties. Found by three independent passes. **Fix:** set `winnerId` when
the shootout resolves (and account for the +1 goal added in the instant-sim path — see #4).

### 4. ○ Cup penalty final score differs between instant-sim and interactive paths
`src/store/slices/orchestration/matchActions.ts (~590)` vs `skipPenaltyShootoutImpl`
Instant-sim does `if (so.winner==='home') hGoals++ else aGoals++`, inflating a 1-1 draw to 2-1/1-2 in
the stored score. The interactive path stores the true drawn score plus `penaltyShootout` metadata.
The same tie reads back a different "final score" depending on how it was played — corrupting cup
history, margins, and match-review displays.

### 5. ✅ AI clubs compute maximum prize money from an empty league table
`src/utils/aiSimulation.ts:87,304,372`
`processAIListings`/`processAIBuying` call `estimateWeeklyIncome(club, [])`. With an empty table,
`tablePos = divisionTable.length = 0`, so `prize = (POSITION_PRIZE_MAX_RANK - 0) * rate` — *more than
1st place*. Every AI club thinks it's flush, disabling wage-crisis sell triggers and wage-to-income
buy guards. AI squads hoard over-budget players and overspend, distorting the transfer market.
**Fix:** pass `state.divisionTables[club.divisionId] || []` and use a bottom-of-table fallback, not index 0.

### 6. ✅ Promotion sponsor bonuses can never be earned (`promoted` hardcoded `false`)
`src/store/slices/sponsorSlice.ts:346` (+ eval at `:515`, satisfaction at `:374`)
`const promoted = false; // No cross-league promotion in single-league mode` — but the game has
promotion, and `'promotion'` is an offered bonus condition on multiple tier-2/3 sponsors
(`sponsorship.ts`: green_earth, steelworks, local_motors, county_build, horizon_tel — exactly the
sponsors a lower-division club gets). `evaluateCondition` does `case 'promotion': return stats.promoted`
→ always false. Lower-division clubs (most starting clubs) can never earn the promotion bonus *or* the
sponsor-satisfaction boost, even when they actually get promoted.

### 7. ✅ Advance-Week button re-enables before `advanceWeek()` finishes → double-advance risk
`src/pages/Dashboard.tsx:1037-1052`
`onClick` sets `isAdvancing(true)`, then a 50ms timeout fires `guardAsync(advanceWeek(), …)`
(fire-and-forget — `advanceWeek` is async, not awaited) and **synchronously** calls
`setIsAdvancing(false)`. The button re-enables ~immediately while the async week-advance is still
running. A fast second tap fires a second `advanceWeek()`, double-processing income/stats/fixtures
(the exact "double advance" class CLAUDE.md warns about). **Fix:** move `setIsAdvancing(false)` into a
`.finally()` on the awaited `advanceWeek()`.

### 8. ✅ Career promotion/relegation reputation only works in the bottom division
`src/store/slices/orchestration/seasonEnd.ts:1486,1491`
Both gates require `replacedSlots > 0`, which is only true for the bottom tier (League Two). Winning
the Championship (promotion to PL) never increments `promotionsWon` or `REP_PROMOTION`; relegation from
PL/Championship/League One never applies `REP_RELEGATION`. Only League Two works, by coincidence.
**Fix:** gate promotion on `leagueInfo.promotionSpots` and relegation on `relegationSpots`.

### 9. ◐ Continental AI finals never resolve (`winnerId` left null)
`src/utils/continental.ts:229-265`
In `simulateKnockoutLeg`, the generic leg-1 branch (`if (leg===1 && !tie.leg1Played)`) fires for *all*
rounds including the Final and returns early, leaving the Final-specific branch (lines 252-265) as
unreachable dead code. The final is simulated but `tie.winnerId` is never set, so the continental
champion is `undefined` and the tournament never completes. **Fix:** check `round === 'F'` before the
generic leg-1 branch.

### 10. ✅ `usePlayerClub()` lies about its type (`Club`, actually `Club | undefined`)
`src/hooks/useGameSelectors.ts:13`
Returns `clubs[playerClubId]` typed as non-optional `Club`, but it's `undefined` when unemployed /
pre-init / mid-migration. Every sibling selector (`useSquadSummary`, `useSquadAverageMorale`) guards
`if (!club)`; this one does not, and callers that destructure it without a guard crash. Latent crash
across many pages. **Fix:** type it `Club | undefined` and audit callers.

### 11. ○ Scout recommendation leaks ground-truth ratings (bypasses fog-of-war)
`src/utils/scouting.ts:64`
`completeAssignment` derives the `sign`/`monitor`/`avoid` badge directly from real `player.potential`
and `player.overall`, ignoring `estimatedOverall`/`knowledge`. A low-knowledge scout still correctly
flags hidden gems, defeating the entire scouting fog system.

### 12. ○ Scout "bust" noise is always positive (overestimate-only)
`src/utils/scouting.ts:56,59`
Both bust branches add `RANGE + random(RANGE)` (always positive), so a misleading report can only make
a bad player look *better*, never make a good player look worse. Removes half the intended scouting risk.

### 13. ○ Youth prospects orphaned in `state.players` every season end
`src/store/slices/orchestration/seasonEnd.ts:1190`
`youthAcademy` is reassigned to the new intake; the prior season's prospect `Player` records are never
removed from `state.players`. 2–4 ghost players accumulate per season indefinitely, bloating saves.

### 14. ○ Youth OVR recalculated with a flat 6-attribute average, not `calculateOverall`
`src/store/slices/orchestration/weekAdvance.ts:1965`
Weekly youth tick computes `newOverall = round((pace+shooting+passing+defending+physical+mental)/6)`
instead of the position-weighted `calculateOverall`. For a GK this inflates OVR ~7 points; the
`Math.max(yp.overall, newOverall)` floor then locks the inflated value, so promotion shows a sudden
unexplained OVR drop.

### 15. ○ Transfer approach on an *unlisted* player always fails
`src/components/game/TransferApproach.tsx:48-55` + `transferSlice.ts:230,276`
The synthetic listing built in the component is never added to `state.transferMarket`, so
`makeOfferWithNegotiation`/`executeTransfer` look it up, find nothing, and return "Player not
available." — for *any* fee. Approaching a player who isn't already listed is completely broken.

### 16. ○ Unemployed career weeks skip `processAIWeekly()` — the AI world freezes
`src/store/slices/orchestration/weekAdvance.ts:524-671`
The unemployed fast-path simulates league fixtures but never runs AI transfers/loans/wages/contracts.
During unemployment AI budgets inflate (no wages paid) and no squads change, producing a distorted
market when the player takes a new job.

### 17. ○ `JSON.stringify(saveData)` is outside the save try/catch
`src/store/slices/orchestrationSlice.ts:297,313`
A serialization throw (circular ref, non-serializable value) propagates uncaught out of `performSave`
(often from an idle callback), the `saveStatus` never goes to `'failed'`, and no Sentry capture fires —
silent data loss.

### 18. ○ Several monetization integrity gaps
- **Free trial re-extends indefinitely** — `monetizationSlice.ts:185`: ✅ guard only blocks *paid*
  tiers, so re-calling `startFreeTrial` during a trial resets the 3-day clock (the JSDoc claim that it's
  a no-op is false). Re-mounting `SubscribeOnboarding` can trigger it.
- **Ad reward non-atomic** — `AdRewardButton.tsx:44-55`: counter increments before `onRewardClaimed()`;
  if that throws / unmounts, the reward is burned with nothing granted. No mutex against double-tap.
- **`Sell All` busy-flag race** — `PacksPage.tsx:141-147`: uses React state, not a ref; two same-tick
  taps both pass the guard and double the sell payout (the `handleOpen` path correctly uses a ref).
- ✅ **Committed RevenueCat sandbox key fallback** — `purchases.ts:21`: if `VITE_REVENUECAT_API_KEY`
  is missing in a prod build, it silently falls back to a hardcoded `test_…` key.

### 19. ○ AI sell-candidate scan aborts the whole loop (`break` vs `continue`)
`src/utils/aiSimulation.ts:141`
`if (club.playerIds.length <= MIN_SQUAD_SIZE) break;` — `playerIds.length` is constant inside the loop,
so once true it skips *all* remaining players. A club at the minimum squad size can never list anyone,
even with 10 players wanting to leave. **Fix:** `continue`.

### 20. ○ Cup/Continental penalties bypass the canonical shootout in two places
- **League Cup** — `tournaments.ts:101-147`: `Math.random() < 0.5` coin flip, ignoring GK quality and
  producing no `PenaltyKick[]`.
- **International knockouts** — `international.ts processKnockoutRound`: `Math.random() > 0.5`, same issue
  (the canonical `simulatePenaltyShootout` is imported but unused).

### 21. ○ International group stage double-books a team in one matchday → a fixture is never played
`src/utils/international.ts:229-242`
Week assignment via `fixtures.length % 3` puts two fixtures sharing a team in the same matchday;
`processGroupWeek` overwrites the first with the second in `playerMatchThisWeek`, leaving the first
`played:false` forever. Affects every international group stage.

# Verification corrections (where audit severity was wrong)

During verification I downgraded two findings the automated passes over-rated:
1. **Celebration "spam every week"** → actually **Low**: Dashboard dedupes via `shownCelebrationsRef`
   keyed by `title-season` (cleared on season change). Real residual issue is a one-time re-fire after
   an app reload because the dedup set is in-memory only.
2. **Incoming offers "never expire" (Critical)** → actually **Medium/latent**: the cross-season
   arithmetic is wrong but currently masked because offers are only created in weeks ≤24 and expire the
   same season.
